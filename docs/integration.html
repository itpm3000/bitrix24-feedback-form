1Авторизация и формат вызова

Все обращения к порталу идут с сервера (бэкенд-прокси). URL вебхука — секрет, в клиентском коде его быть не должно: браузерная форма шлёт данные на ваш бэкенд, а он — в Bitrix24.

BASE = https://<portal>.bitrix24.ru/rest/<user_id>/<webhook_token>/
Вызов метода

POST {BASE}<method>.json, заголовок Content-Type: application/json, тело — JSON с параметрами метода.

Обязательно

Непустой заголовок User-Agent — портал режет запросы без него. Успех — поле result; ошибка — error + error_description.

2Логика в трёх шагах

Антидубль контактов встроен: повторная отправка того же email/телефона не плодит контакты.

01
Поиск дубля
по email и телефону среди контактов
02
Контакт
создать, только если дубль не найден
03
Сделка
создать с CONTACT_ID — новым или найденным

Ниже два эквивалентных способа. Подход A проще в реализации (обычные последовательные вызовы). Подход B — оптимизация через batch (меньше запросов, важно на объёмах).

3Подход A — последовательные вызовы

Рекомендуется по умолчанию: прозрачно и легко отлаживать.

Шаг 1 · Поиск дубля контакта

Вызвать по каждому заполненному каналу связи.

POST {BASE}crm.duplicate.findbycomm.json
{ "entity_type": "CONTACT", "type": "EMAIL", "values": ["ivan@example.com"] }
// и/или
{ "entity_type": "CONTACT", "type": "PHONE", "values": ["+79001234567"] }

Ответ при совпадении: { "result": { "CONTACT": [16] } } — берём первый ID. Пустой массив / нет поля — дубля нет.

Шаг 2 · Создание контакта (только если дубля нет)

POST {BASE}crm.contact.add.json
{
  "fields": {
    "NAME": "Иван",
    "LAST_NAME": "Петров",
    "OPENED": "Y",
    "TYPE_ID": "CLIENT",
    "SOURCE_ID": "WEB",
    "EMAIL": [{ "VALUE": "ivan@example.com", "VALUE_TYPE": "WORK" }],
    "PHONE": [{ "VALUE": "+79001234567", "VALUE_TYPE": "WORK" }],
    "IM": [{ "VALUE": "@ivan_petrov", "VALUE_TYPE": "TELEGRAM" }],
    "UF_CRM_1786546554": "site-a.com:user-42"
  }
}

Ответ: { "result": 123 } — ID нового контакта.

Множественные поля

EMAIL и PHONE передаются массивом объектов {VALUE, VALUE_TYPE}, а не строкой. VALUE_TYPE: WORK · MOBILE · HOME · OTHER.

Шаг 3 · Создание сделки

POST {BASE}crm.deal.add.json
{
  "fields": {
    "TITLE": "Обращение с сайта site-a.com — Иван Петров",
    "CATEGORY_ID": 2,
    "STAGE_ID": "C2:NEW",
    "CONTACT_ID": 123,
    "ASSIGNED_BY_ID": 22,
    "SOURCE_ID": "WEB",
    "SOURCE_DESCRIPTION": "site-a.com | https://site-a.com/contacts",
    "COMMENTS": "Текст обращения + сводка по источнику",
    "UF_CRM_1786700225371": "Не проходит платёж по QR",
    "UF_CRM_1786685648580": 188,
    "UF_CRM_1786685952807": 158,
    "UTM_SOURCE": "google", "UTM_MEDIUM": "cpc", "UTM_CAMPAIGN": "helpdesk"
  }
}

Ответ: { "result": 4567 } — ID сделки. Поле CONTACT_ID связывает сделку с контактом. Если контакт найден на Шаге 1 — Шаг 2 пропускается, а сюда идёт найденный ID.

4Подход B — batch (одним запросом)

Метод batch выполняет до 50 команд за один HTTP-запрос и подставляет результат предыдущей команды в следующую через $result[<ключ>].

Грабли · формат команд

Сырой endpoint batch принимает команды строками вида "<method>?<url-encoded-параметры>". Форму { method, params } он молча игнорирует — вернётся пустой result. Объекты понимают только клиентские библиотеки (CRest::callBatch, BX24.callBatch), которые сами конвертируют их в строки.

POST {BASE}batch.json
{
  "halt": 1,
  "cmd": {
    "contact": "crm.contact.add?fields[NAME]=Иван&fields[EMAIL][0][VALUE]=ivan%40example.com&fields[EMAIL][0][VALUE_TYPE]=WORK",
    "deal": "crm.deal.add?fields[TITLE]=Обращение&fields[CATEGORY_ID]=2&fields[STAGE_ID]=C2:NEW&fields[CONTACT_ID]=$result[contact]"
  }
}

halt:1 — остановить пакет при первой ошибке. fields[CONTACT_ID]=$result[contact] подставит ID контакта из команды contact. В ответе: result.result.contact, result.result.deal; ошибки по командам — в result.result_error.<ключ>.

Грабли · нет транзакции

batch не транзакционный: если контакт создан, а сделка упала, контакт не откатывается. Чтобы не плодить «висячие» контакты — при наличии result.result.contact и отсутствии result.result.deal удалить контакт: POST {BASE}crm.contact.delete.json с телом { "id": <contactId> }.

6Ошибки и лимиты

СитуацияПризнакЧто делать
Нет праваinsufficient_scopeвыдать вебхуку scope crm
Лимит интенсивностиQUERY_LIMIT_EXCEEDED · HTTP 503ретрай с паузой; ведро 50 запросов, слив 2/сек на портал (Enterprise — 250 / 5)

7Порядок реализации на бэкенде

01 · Приём
принять POST формы, провалидировать email/телефон и обязательные поля
02 · Источник
снять на клиенте домен, URL страницы, referrer, utm_* и передать на бэкенд
03 · Дубль
поиск существующего контакта по email и телефону
04 · Создание
контакт (если нужно) + сделка с CONTACT_ID в воронке HelpDesk
05 · Ответ
вернуть форме ID сделки/контакта или текст ошибки
